## 本轮踩坑（新增）

- **Edit 工具会"吃掉"函数体**：一次想在 `plugin_data_get` 前插入新命令的编辑，`old_string` 只写到
  函数签名行，结果整个函数体被删、文件语法残缺。教训：修改区域必须**整段包含**，
  不要拿"半个函数"当锚点；改完立刻回读该文件。
- `npm install -D @eslint/js` 默认拉 v10 会与 `eslint@^9` 冲突（ERESOLVE），需显式写 `@eslint/js@^9`。
- `eslint-plugin-react-hooks` v7 的 `recommended-latest` 带出一批实验性规则
  （`set-state-in-effect` / `use-memo` / …），对存量代码直接报 32 个 error；
  **只显式启用 `rules-of-hooks` + `exhaustive-deps`** 才是可用的门。
- `PluginDataStore.bind()` 的方法原本会在插件卸载后**同步抛出**（`resolve()` 直接在箭头函数体里调用），
  调用方 `.catch()` 捕不到；已改为 `async` 箭头函数，统一变成 rejected promise。

## UI 精简优化 + 现代化 + Logo（同日晚）

### 根因：Tailwind v4 从未真正生效

- 项目装了 `tailwindcss@^4.1.18`，但 `index.css` 用的是 **v3 的 `@tailwind` 指令**，
  且缺 PostCSS 配置、`vite.config.ts` 里也没挂 Tailwind 插件 → **所有 JSX 上的 utility class 全是死代码**。
- 真正在起作用的是 916 行手写 `styles.css`（假 utility shim，含语法错误与环境级
  `button { background: gray }`）—— 这就是"粗糙感"的源头。
- 修复：装 `@tailwindcss/vite`（Node `spawnSync('npm.cmd', …)`，bash 不可用）→
  `vite.config.ts` 挂插件 → `index.css` 按 v4 重写为完整设计系统 → 删 `styles.css` /
  `App.css`（Vite 模板残留）/ `tailwind.config.js`（v3 遗留）。

### `src/index.css` 设计系统（v4 写法，约 480 行）

- `@import 'tailwindcss'` + `@custom-variant dark (&:where(.dark, .dark *))`。
- `:root` / `.dark` 只改变量值：`--canvas/--surface/--surface-2/--line/--ink(1/2/3)/--brand/--ok/--warn/--danger`，
  `@theme inline` 映射成 `bg-surface` / `text-ink` / `border-line` 等语义类。
- 组件层 `.card/.btn/.btn-primary/.btn-ghost/.btn-sm/.icon-btn/.input/.seg/.seg-item/.chip/.label/.tnum`，
  状态用 `data-active`；关键帧 `taskEnter/taskLeave/taskDone/checkPop/panelIn/cellPop/modalEnter/tabEnter/statFlash`。
- **暗色兼容层必须放在 `@layer` 之外**（unlayered 优先级高于 `@layer`），用
  `:not([class*='dark:…'])` 跳过自带 dark 变体的元素，避免破坏 `bg-gray-900 dark:bg-white` 反色按钮。
