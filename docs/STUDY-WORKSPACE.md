## 0. 一句话定位

> 任务列表负责**生成计划**，学习工作区负责**执行计划**：
> 一次只给"下一条该做的"、把计划推荐的内容读到应用里、用计时器把学习时长变成事实、
> 让辅导员**只依据正文**回答问题，最后把"预估 vs 实际"回流成记忆，让下次的计划更准。

**30 秒口语版**：
> 我的项目原本只能生成计划，学不学得下去它不管。所以我加了一个工作区：
> 进来只显示今天该做的那一条（和任务栏的计划队列同一套语义），右边能读白名单站点的正文，
> 侧栏有番茄钟和速记，还有一个辅导员 —— 但它**必须先在这条资源的正文里检索到依据才回答**，
> 检索不到就直说"这条资源里没有"，根本不调模型。学完写三行总结，顺手把复习排到 1/3/7/16 天，
> 并把"预估 30 分钟、实际 47 分钟"写进记忆 —— 下次生成计划时它会被召回。
> 整个闭环的关键是最后这条：**计划会自己变得越来越准**。

## 1. 可行性结论：拼装，不是重写

| 需要的能力 | 结论 | 落点 |
|---|---|---|
| 页面与导航 | 新写（很薄） | `src/App.tsx` 一条 Route、`src/components/Layout.tsx` 一项 `primaryNav` |
| 独立数据域 | 新写（薄） | `src/api/studyStore.ts`，照抄 `scheduleStore`：`PluginDataStore` + `__study` 命名空间 |
| 数据持久化 / 备份 | **零改动** | 宿主保留命名空间随 `dumpAll()` 全量导出；只在报告里单独计数 |
| 计划推荐资源 | **复用** | `plan.resources` / `plan.evidence`，经 `features/study/planLink.ts` 还原到任务 |
| 聚焦"下一条待做" | **复用** | `plan-generator/services/planQueue.ts`（与任务栏同一套语义） |
| 正文抓取 / 缓存 | **复用** | `rag/contentFetcher.ts`（含 SSRF 与体积上限）、`rag/contentCache.ts` |
| 分块 / 向量 / 检索 | **复用** | `rag/chunking.ts`、`rag/vectorStore.ts`（独立命名空间）、`rag/embedding.ts` |
| 提示注入隔离 | **复用** | `agent/promptGuard.ts` |
| 模型传输 | **复用 + 一处新增** | `llm/chatClient.ts` 新增 `streamChat`（流式是本地模型上体验的最大杠杆） |
| 调度 / 轨迹 / 记忆 | **复用** | `llmTaskManager`（`kind:'study'`）、`agent/trace.ts`（`TraceKind` 加 `'study'`）、`memory/*` |
| 番茄钟 | **全新** | 全仓此前没有任何计时器实现 |
| 辅导 Agent 的检索闭环 | **新写（薄）** | `features/study/tutor.ts`（约 300 行，复用上面全部基础设施） |

**最容易被低估的三件事**（本次都已落地，写法见对应小节）：

1. 多轮辅导其实需要**流式**输出（本地 7B 模型非流式要等十几秒）—— 新增 `streamChat`。
2. 番茄钟是零基础新增（状态机 + 真实时间差 + 暂停语义）。
3. "正文长期保存"是**产品/隐私决策**而不是编码决策 —— 最终结论：正文只缓存 7 天不进备份，
   长期留存的是用户自己写的笔记与计划里的 240 字摘要。

## 2. 信息架构（页面长这样）

```
学习工作区 /study
┌─────────────────────────────────────────┬──────────────────┐
│ ① 当前任务卡：目标 + 第 2/6 条 + 任务详情 │  🍅 番茄钟        │
│ ② 推荐内容：1–3 条资源（进度 / 摘要）      │  📅 复习安排      │
│ ③ 开始学习 → 收工（总结 + 是否达成）       │  📝 速记          │
├────────────────────────┬────────────────┤                  │
│ ④ 阅读模式（纯文本）    │ ⑤ 学习辅导员     │                  │
└────────────────────────┴────────────────┴──────────────────┘
```

刻意做的几个"减少决策"的决定：

1. **进来只给一条**：与任务栏的逐条解锁一致，不用再选一次。没有计划任务时退化为第一条未完成的普通任务，
   工作区照样可用（不会变成一个空页面）。
2. **资源只显示当前任务引用的那几条**，不做"全部资源库"（资源库在向导里已经有了）。
3. **收工必须产出东西**（三行总结或复习安排）——这是唯一能对抗"收藏了=学会了"的设计。

## 3. 三个产品决定与落点

### 3.1 应用内阅读：白名单域名 + 还原原网站 Markdown + 阅读优先版面

`features/study/reading.ts` 把"能不能读"翻译成可解释的原因，界面上给出**最短路径**：

| 情况 | `status` | 界面给的动作 |
|---|---|---|
| 正文抓取未开启 | `disabled` | 打开设置（语义检索 → 正文抓取） |
| 白名单为空 | `blocked` | 打开设置 + 说明"留空表示不抓任何站点" |
| 域名不在白名单 | `blocked` | **一键把该域名加入白名单**（`useEmbeddingSettings().update`）+ 设置页指引 |
| 命中 7 天缓存 / 本次抓取 | `cache` / `fetched` | 直接渲染正文（标明来源与字数） |
| 抓取失败 | `failed` | 原样显示失败原因 + 在浏览器打开 |

抓取依然受既有三重约束：**白名单 + 拒内网（Rust `content::is_public_host`）+ 800KB / 12000 字上限**。

#### 一次抓取，两种输出：检索要干净，阅读要结构

最初 `fetch_page_text` 只返回纯文本，结果是"标题 / 加粗 / 代码块"到了阅读界面全变成同一种灰字 ——
阅读模式的价值本来就是**让重点看得出来**，所以现在同一次抓取产出两份：

| 输出 | 谁在用 | 为什么 |
|---|---|---|
| `text`（纯文本） | 分块、向量、证据、辅导员检索 | 标记对检索是噪声（`**` 会进 embedding 与 chunk），文本越干净越好 |
| `markdown` | **只给阅读模式** | 保留标题层级 / 加粗 / 列表 / 代码块 / 引用 / 链接，阅读时重点可辨 |

`markdown` 由 Rust 的 `content::html_to_markdown` 从同一份 HTML 转换而来（纯函数 + 单测）：

| HTML | Markdown | 说明 |
|---|---|---|
| `<h1>`–`<h6>` | `#`–`######` | 标题层级是"重点"里最重要的一层 |
| `<strong>/<b>`、`<em>/<i>`、`<del>` | `**`、`*`、`~~` | 行内强调 |
| `<code>`、`<pre>` | `` ` ``、围栏块 | 代码块**原样保留**（含其中的 `#`、`<`；语法高亮的 `<span>` 被剥掉） |
| `<ul>/<ol>/<li>` | `- ` / `1. `（缩进 2 空格/层，封顶 3 层） | 列表 |
| `<blockquote>` | `> ` | 引用 |
| `<hr>` | `---` | 分隔 |
| `<a href="https://…">` | `[文字](url)` | **只接受绝对 http(s)**；相对链接、`javascript:` 一律退化成纯文字 |

另外：响应本身就是 Markdown（`content-type` 含 `markdown`，例如 GitHub README 的 `.md` 链接）时，
直接原样截断作为 `markdown` —— 那种情况下"原网站格式"就是 Markdown 本身。

#### 渲染：结构 → React 元素（不走 innerHTML）

`features/study/markdown.ts` 是阅读用的 **Markdown 子集解析器**（纯函数，11 条单测），
`components/MarkdownText.tsx` 把它映射成 React 元素：

- **没有 `dangerouslySetInnerHTML`**：正文来自外部网站，必须当不可信内容处理；
  解析结果直接变成元素，从构造上就不存在注入面（用例会断言 `<script>` / `<img onerror>` 只以转义文字出现）；
- 链接只接受 http(s)，点击走系统浏览器打开（不在应用内跳转）；
- 明确**不做**的语法：表格、任务列表、脚注、HTML 内联、嵌套强调的多层解析 ——
  不认识的语法就当普通文字显示，"少渲染一层"远好于"显示成乱七八糟"。

#### 版面：阅读优先

- 正文限宽 **~68 字符**、行高 1.9、字号可调（em 单位，标题/代码跟随缩放）；
- 读到正文后**自动进入「专注阅读」**：正文占满主区，任务卡 / 复习 / 速记让位，
  辅导员与番茄钟退到侧栏（窄列），顶部状态条保留「开始/结束学习」与「退出专注阅读」；
- 卡片只剩一条工具条（标题 · 来源 · 字数 · 格式状态），把纵向空间全留给正文；
- **优雅回退**：没有 `markdown` 时（浏览器直连分支、旧缓存）渲染纯文本段落，并明确提示
  "当前是纯文本模式（桌面端读取可保留标题与重点格式）" —— 不假装有格式，也不静默降级。

### 3.2 会话与笔记纳入备份

`__study` 命名空间走 `PluginDataStore`：`dumpAll()` 是**按命名空间全量导出**、`restoreRows()` 逐行写回，
所以学习数据**本来就随备份导出/恢复**，不需要改 `BackupFile` 结构。

为了让用户**看得见**，做了两件小事：

- `backupService.countStudyRows(rows)`：按命名空间统计学习工作区的行数；
- `RestoreReport.studyRows` + `DataBackupCard` 的文案里显示"含学习工作区 N 条" / "学习工作区 N 条"。

> 备份这种功能，"能在界面上核对"比"写在说明里"重要得多 —— 这条是这个决定的全部理由。

### 3.3 辅导员默认禁止无依据回答

`features/study/tutor.ts` 的流程：**先在"当前资源的正文"里做向量检索，检索不到就直说，不调用模型**。

```
提问
 ├─ 没有正文            → no_evidence（不调模型）
 ├─ 未开启本地模型       → failed（不调模型）
 ├─ embedding 报错       → failed（不调模型，"无法确认依据，因此不回答"）
 ├─ 检索不到相关片段      → no_evidence（不调模型）       ← 决定 #3 的核心
 └─ 检索到片段           → 包成"不可信数据"块注入 → 流式生成 → 引用白名单校验
```

为什么这么硬：本地 7B 模型在没有依据时几乎一定会编，而**学习场景里"编一个错的解释"比"什么都没说"有害得多**。
这也让"防幻觉"从文案变成**可断言的行为**：`tutor.test.ts` 里有一条用例专门断言"拒绝时模型的调用次数为 0"。

回答侧的纪律与项目既有做法完全一致：

- 片段经 `promptGuard.wrapUntrustedData` 包裹，system 里声明其不构成指令；
- 只能引用本次注入的 `E1..En`，编造的编号**丢弃并计数**（`parseTutorCitations` 返回 `dropped`），
  界面上明确显示"模型还标了 N 处找不到的引用，已按白名单忽略"；
- 每一步都写进 trace（`TraceKind: 'study'`），包括"为什么拒绝"，在设置页「运行轨迹」里可回看。

## 4. 回流闭环（这个项目最值钱的一条）

```
计划生成（预估每天 60 分钟）
    ↓
学习工作区执行（实际 47 分钟）
    ↓
收工时写记忆：预估 / 实际 / 偏差（sessionMemory.buildStudySessionNote）
    ↓
下次生成计划时召回记忆（memory.recallForGoal）
    ↓
模型据此调整每日投入
```

记忆的合并键带 `study:` 前缀（`study:<归一化目标>`），**故意与"计划是否被接受"那条记忆区分开** ——
否则同一目标的两条记忆会互相覆盖（`mergeMemoryNotes` 按 `kind + subjectKey` 合并）。

## 6. 明确不做（这些是反模式）

1. **不做"万能聊天助手"入口** —— 上下文失控、幻觉、成本，且与"聚焦"的气质相反；辅导员只在有正文时可用。
2. **不新建第二套任务系统** —— 学习/复习任务继续用 `tasks` 表 + 标签，走既有 `createTask` / `patch_task`。
3. **不为工作区新增 Rust 表或字段** —— `plugin_data` 的命名空间完全够用。
4. **不做应用内嵌浏览器** —— webview iframe 外部站点基本不可用（X-Frame-Options/CSP），安全面也大。
5. **不长期保存抓来的正文** —— 只用 7 天缓存；长期留存的是用户自己写的笔记与计划里的摘要。
   （`markdown` 与 `text` 一样只在缓存里活 7 天，随缓存一起被淘汰与清除。）
6. **不做完整 SM-2 复习算法** —— 输入只有"学完了"，没有每次复习的自评质量；用不起的数据不假装用。
7. **不还原原站排版** —— 只还原**语义结构**（标题/重点/列表/代码/引用）；不复刻 CSS、不加载图片、
   不做表格与站内跳转。目标是"重点看得出来"，不是"把网页搬进来"（后者需要完整渲染引擎，
   还会把外部样式与脚本带进应用，安全面与体积都不划算）。
